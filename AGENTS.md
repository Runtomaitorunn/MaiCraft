# Project Instructions

This repository is Ye Mai's personal portfolio site. For UI, visual design, frontend polish, copy, motion, responsive behavior, accessibility, or portfolio content work, use the local Impeccable skill installed at `.github/skills/impeccable/`.

Before making design-facing changes:
- Read `PRODUCT.md` for strategy, audience, register, brand personality, anti-references, and design principles.
- Read `DESIGN.md` for the current visual system, tokens, components, motion posture, and do/don't rules.
- Run `node .github/skills/impeccable/scripts/context.mjs` once per session and follow its output.
- If a specific Impeccable command is relevant, read `.github/skills/impeccable/reference/<command>.md` before acting.
- After analysis and direction are resolved, read `.github/skills/impeccable/reference/craft-floor.md` immediately before editing UI.

Default design posture:
- Treat this as a brand/portfolio surface, not a product dashboard or corporate site.
- Preserve the Fresh, young, bold, technical identity.
- Keep the site commercially useful for employers, collaborators, and mentors.
- Avoid generic corporate homepage patterns, AI SaaS tropes, bland template grids, and visual choices that hide Ye Mai's creative and technical personality.

Useful Impeccable command mappings:
- Use `init` only when refreshing project context.
- Use `document` when the visual system changes enough that `DESIGN.md` should be updated.
- Use `critique` for UX/design review.
- Use `audit` for accessibility, performance, responsive, and technical quality checks.
- Use `polish`, `layout`, `colorize`, `typeset`, or `animate` for focused refinement.
- Use `live` for browser-based visual variant iteration when a local server is running.
